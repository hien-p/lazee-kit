# Builder Implementation Brief

This file tells the later implementation agent how to use the design system. It is not app code.

## Read First

1. Read `04-design-tokens.md`.
2. Read `05-mascot-system.md`.
3. Read `07-ui-components.md`.
4. Read `08-page-and-demo-templates.md`.
5. Read the proposal docs in the parent folder.

## Implementation Priorities

1. Establish tokens and global visual rules.
2. Create or generate mascot and sticker assets.
3. Build the proposal landing page.
4. Build the demo flow page.
5. Build the architecture page.
6. Build the pitch deck page.
7. Polish mobile layout.
8. Capture screenshots for SCF submission.

## Do Not Invent

- Do not invent new colors without adding them to tokens.
- Do not add generic Web3 gradients.
- Do not make the mascot the only evidence for safety.
- Do not replace technical proof with decorative cards.
- Do not create product code while working only on artifacts.

## Quality Bar

The final visuals should make Lazee feel:

- easier than a wallet setup
- more complete than a passkey demo
- safer than agent key sharing
- more reusable than a single app
- credible enough for technical SCF reviewers
