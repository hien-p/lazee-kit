# Demo MVP Plan

## Demo Title

**From first visit to first Stellar action in under 60 seconds.**

## Demo Goal

The demo should prove that Lazee Kit is not just architecture. It should show a complete sponsored-action journey that a reviewer can understand without installing anything.

## 3-Minute Flow

### Beat 1: New User, No Funding Setup

Open the reference app with a fresh browser profile. The page shows one simple app action and makes clear that the user does not need to manually fund XLM before trying it.

Show that the first action is a real Stellar transaction, not a mock.

### Beat 2: Approve One Clear Action

The user connects or selects a supported Stellar signer and approves a single described action.

The UI shows:

- action preview
- expected result
- sponsor status
- network and fee disclosure

### Beat 3: Sponsor And Submit

Show the sponsor helper status moving through:

1. Simulate
2. Sponsor
3. Submit
4. Confirm

Copy:

> This app sponsors your first Stellar action.

### Beat 4: Receipt And Next Step

Show:

- transaction hash
- network status
- fee sponsor status
- user-readable receipt
- next action for the app

## Why This Looks Better

| Alternative | Demo Weakness | Lazee Demo Advantage |
|---|---|---|
| Wallet-only onboarding | User still has to understand funding and fee setup | App embeds the first-action flow directly |
| Passkey-only demo | Authentication works, but no Stellar outcome is proven | User completes a real sponsored Stellar transaction |
| Funding-only helper | Transaction works, but app experience remains incomplete | Lazee includes UI, SDK, receipts, docs, and runbooks |
| Generic relayer | Trust model unclear | Sponsor helper pays fees only after simulation and user approval |
| Broad automation platform | Too much scope to review cleanly | Lazee focuses on one verifiable first-action path |
